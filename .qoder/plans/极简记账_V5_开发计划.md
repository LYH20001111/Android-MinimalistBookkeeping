## 2. 技术选型

### 2.1 OCR：ML Kit 文字识别（端侧中文模型）

- 依赖 `com.google.mlkit:text-recognition-chinese:16.0.1`，模型随 APK 打包，**离线可用、不依赖 Google Play Services**（国内设备可用）。
- `InputImage.fromFilePath()` 自动处理 EXIF 方向；原图先降采样到 ≤2048px 再送识别，控内存。
- OCR 只负责「图 → 文本」（基线第 6 章），业务理解全部交给 AI 解析层。

### 2.2 AI 解析：双 Provider（接口抽象 + 离线兜底）

- `AiTransactionParser` 接口，两个实现：
  - `CloudAiTransactionParser`：OpenAI 兼容 `/chat/completions`，输出强制 JSON（基线第 26 章）；Base URL / Key / 模型名由用户在设置页配置，存 SharedPreferences（仿 `ServerConfigStore`）。
  - `LocalRuleTransactionParser`：纯正则 + 关键词词典，覆盖「金额 / 类型 / 相对日期 / 分类关键词 / 商家」；**离线可用**，同时作为云端失败 / 未配置时的兜底。
- `AiRepository` 按配置路由：已配置云端 → 云优先、失败降级本地；未配置 → 直接本地。UI 永远不直接触碰 AI SDK（基线第 28 章）。

### 2.3 相机与相册

- 拍照：`ActivityResultContracts.TakePicture` + `FileProvider` 临时 URI，**不申请 CAMERA 权限**（系统相机完成拍摄，权限体验最轻）。
- 相册：`ActivityResultContracts.PickVisualMedia`（Android Photo Picker，免存储权限）。
- 临时图片存 `cacheDir`，生成草稿后立即删除（基线第 32 章），V5 不保存票据附件。

### 2.4 网络与失败降级

- 复用 OkHttp（项目已有），独立轻量客户端，超时 connect 8s / read 30s。
- 断网 / 云端失败 → 降级本地规则解析；本地也失败 → 确认页留空金额人工填写（基线第 9、35 章：任何失败不阻断手动记账）。

## 3. 关键设计决策

1. **确认页独立成页**（`ConfirmBillActivity`），不复用「记一笔」表单：需要展示「识别来源 + 请确认」提示、低置信度字段警示（基线第 7、8 章），且确认页按钮语义是「确认记账 / 重新识别」。
2. **不修改 Room schema**：基线第 31 章允许「来源 / 置信度只存草稿不落库」。加列会连带 Room 迁移 9→10、同步协议 4、服务端 schema 变更，收益不匹配成本，V5.0 先不做。
3. **商家字段折入备注**：`TransactionEntity` 无 merchant 列，识别出的商家与备注合并写入 `note`（商家在前、去重），确认页展示为一个「备注」输入框。
4. **账户默认落首个未归档账户**：草稿无账户概念，确认页提供账户下拉（默认首选），与「记一笔」一致保证 `account_id` 非空。
5. **转账不支持**：扫描 / 描述场景无转账语义，确认页类型切换只有支出 / 收入。
6. **入口只挂新增模式**：编辑模式右上角已有退款菜单，且基线定位是「记一笔时增强」，编辑旧账单不挂 ✨。
7. **置信度**：云端返回模型自评置信度（0~1000）；本地规则按匹配强度给固定档位。UI 只映射为「正常 / 请确认 / 请手动填写」三档（基线第 8 章），不展示数字。

## 4. 架构与文件清单

```text
ai/                                    ← 新增包（基线第 27 章）
├── TransactionDraft.java              统一草稿模型（type/amount/categoryId/date/time/note/merchant/source/confidence）
├── DraftValidator.java                校验层：amount>0、type/categoryId/date/time 合法（基线第 25 章）
├── AiTransactionParser.java           解析接口：text + 分类候选 → Draft
├── CloudAiTransactionParser.java      OpenAI 兼容实现（OkHttp + Gson，强制 JSON 输出）
├── LocalRuleTransactionParser.java    离线规则实现（金额/日期/类型/分类/商家正则词典）
├── OcrService.java                    OCR 接口：Uri → OcrResult(文本行)
├── MlKitOcrService.java               ML Kit 实现
├── OcrTextCleaner.java                小票文本清洗（合并行、过滤噪音行）
├── AiRepository.java                  管线编排：图片→OCR→清洗→解析→校验→Draft；文字→解析→校验
├── AiConfigStore.java                 AI 服务配置持久化（baseUrl/apiKey/model）
└── AiResult.java                      解析结果封装（draft + 来源 + 错误类型）

ui/smart/                              ← 新增包
├── ScanBillActivity.java              拍照/相册 → 处理中 → 跳确认页；失败弹窗不阻断
├── ScanBillViewModel.java             IDLE/PROCESSING/ERROR 状态机
├── AiBookkeepingActivity.java         文本输入 → 解析 → 跳确认页
├── AiBookkeepingViewModel.java        输入/解析状态机
├── ConfirmBillActivity.java           账单确认页（可编辑全部字段 + 确认落库）

├── AiSettingsActivity.java            AI 服务配置页
└── SmartEntryPopup.java               ✨ 菜单弹层逻辑（复用自绘 PopupWindow 模式）
```

## 5. 交互流程

```text
TransactionEditActivity（新增模式，工具栏 ✨）
├── 扫描账单 → ScanBillActivity
│     拍照(TakePicture) / 相册(PickVisualMedia)
│     → PROCESSING（正在识别…）
│     ├─ 成功 → ConfirmBillActivity（携带 Draft）
│     ├─ OCR 无文字 → 弹窗：重新拍摄 / 选择其他图片 / 手动填写
│     └─ 解析失败 → 弹窗：重试 / 手动填写（保留已识别信息）
└── AI 智能记账 → AiBookkeepingActivity
      文本输入（示例提示语）→「开始识别」
      ├─ 成功 → ConfirmBillActivity
      └─ 失败 → 页内提示：重新尝试 / 手动填写

ConfirmBillActivity（类型/金额/分类/账户/日期/时间/备注 均可修改）
├── 确认记账 → 校验 → repository.saveTransaction → 「已记账」→ 级联 finish 回记录页
└── 返回 → 回到来源页（重新扫描 / 改描述）
```

级联关闭：Edit → Scan/AI → Confirm 全链路 `for result`，确认成功后逐级 `setResult(RESULT_OK)` + `finish()`，落回记录页（新增账单经 LiveData 自动出现）。

首次使用引导：新增模式首次进入时 Snackbar 轻提示一次（`Prefs` 记 flag），「知道了」后不再出现（基线第 41 章）。

## 7. 测试计划

### JVM 单测（test/）

- `LocalRuleTransactionParserTest`：
  - 基线第 52 章正例：`今天午餐32`、`昨天午餐32`、`昨晚吃饭128`、`工资到账8500`、`买耳机599`、`地铁6块`、`今天早上地铁花了6块`、`星巴克买了一杯咖啡35`
  - 边界（不得臆造金额）：`花了一百多`、`昨天吃饭`、`买了东西`、`工资发了` → 金额缺失、走确认
  - 金额格式：`35.5`、`35.50`、`¥42`、`6块`；类型：收入关键词；相对日期：今天/昨天/前天/X月X日
- `DraftValidatorTest`：amount<=0、非法 type、未匹配 categoryId、空时间等拒绝路径
- `OcrTextCleanerTest`：行合并、噪音过滤、多金额行保留（交给解析层判断实付）

### 人工验收（对齐基线第 53 章）

1. 清晰小票照片 → 金额/日期/商家识别 → 确认页可改 → 落库记录页可见
2. 相册截图（微信/支付宝账单）→ 同上
3. 一句话文本 6 条正例 → 草稿正确 → 确认落库
4. 模糊图片 / 无金额图片 → 提示但不阻断，手动补全可保存
5. 断网全流程（OCR 端侧 + 本地规则）可用
6. 手动记账主流程与编辑/退款（V4）无回归

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| ML Kit 中文包体积增加（约 20-40MB） | 接受：换取离线可用与免 GMS；后续如需可切 unbundled 版本 |
| 云端 LLM 返回不合法 JSON | 响应清洗（剥 markdown 围栏）+ 失败降级本地规则 |
| 本地规则误判分类 | 一律落入「建议」语义：确认页分类可一键重选，低置信显示「请确认」 |
| 多金额小票选错实付 | 解析层提示词/规则优先「实付/合计/应付」关键词；不确定标记「请确认」 |
| TakePicture 被厂商相机取消 | URI 沿用，用户可重拍或改相册，无状态残留 |

1. 语音记账未做（P1，符合范围）；`AiBookkeepingViewModel` 已预留同一解析管线。
