# 极简记账 V2.1 开发计划

> 依据：《极简记账App_V2.1_产品设计与开发基线.md》
> 版本主题：**体验优化 + 数据一致性 + 长期稳定性**
> 状态：**已开发完成**（2026-09-04）。构建、193 个 JVM 单测、12 个真机仪器测试全部通过；
> 新增偏离项见文末「实施备注」。

## 实施备注（与基线的差异及理由）

1. **Migration 锚点回填取 `day(start_date)` 而非基线建议的 `day(next_run_date)`**
   （基线 15.2）：`saveRecurring` 新建时 `nextRunDate = startDate`，两者通常相同；
   但已发生月末夹取漂移的存量规则若按 `next_run_date` 回填会把漂移固化成新锚点，
   按 `start_date`（用户最初选择的日期）回填才符合「修复漂移」的版本目标。
   已由 `MigrationTest.migrate_v3WithRecurring_backfillsAnchorFromStartDate` 在真机锁定。
2. **备份恢复版本策略放宽为「≥3 即可恢复」**：V2 的 v3 备份缺锚点日字段，
   序列化侧按 `day(start_date)` 推导补齐（基线 31.5 的兼容要求）；高于当前版本的文件仍拒绝。
3. **搜索选择器输入框**由 `MaterialAutoCompleteTextView` 改为只读 `TextInputEditText` +
   普通样式（不能沿用 ExposedDropdownMenu 样式——Material 在运行时强制要求该样式的
   子控件是 AutoCompleteTextView，混用会 InflateException 崩溃）；尾部图标改为
   `endIconMode="custom"` 的下箭头并接入点击，保住「可展开」的手感。
   已由真机仪器测试 `SearchActivitySmokeTest`（启动 + 渲染 + 弹窗布局加载）与
   真机 UI 走查（记录页 → 搜索 → 分类 / 账户选择器弹窗）双重锁定。
4. **最高点气泡避让**在 V2 已具备（顶部越界下移 + 左右越界内移），本版保留并回归验证。
5. **横向滚动**：月 / 年默认不做（基线 10.1），长周期局部横滑仅预留不实现。

## 1. 现状盘点（计划编制时对 V2 代码的实测结论）

开发计划编制前逐文件核对了 V2 工程，以下事实决定了各 Phase 的实际工作量：

| 领域 | 现状 | 与基线差距 |
|---|---|---|
| 数据库 | `AppDatabase` version 3，`MIGRATION_1_2`、`MIGRATION_2_3` 集中管理，外键 RESTRICT | 需新增 `MIGRATION_3_4` |
| 周期账单 | `GenerateRecurringTransactionsUseCase.nextAfter` 用 `Calendar.add` 平移，月/年日越界被夹取后**从夹取结果继续推进**（1/31→2/28→3/28 漂移） | 需引入 `anchor_day_of_month`，每次从原始锚点重推 |
| 周期账单创建 | `saveRecurring` 新建时 `nextRunDate = startDate`，故 `day(start_date)` 即用户最初选择的锚点日 | Migration 锚点回填应取 `day(start_date)`（比基线建议的 `day(next_run_date)` 更优：已漂移的数据不会把漂移固化） |
| 图表 | `LineChartView` 已有标签抽样（月视图 1/5/10/15/20/25 + 末日）、`labelIndices()` 静态可测；最高点气泡已做上越界下移 + 左右夹取 | 缺：绘图区左右安全边距（首末点贴边、末标签裁切）；标签按宽度自适应降采样；不重叠校验 |
| 搜索选择器 | 分类/账户是 `MaterialAutoCompleteTextView` 纯文字下拉（`setSimpleItems`） | 需改为图标网格 / 图标列表弹窗 |
| 搜索统计 | `search_summary_format`「共 N 笔 · 支出 · 收入」已实现，转账计入笔数不计收支 | 已满足，仅回归验证 |
| CSV 导入 | `ImportRowClassifier` 判「疑似重复」后**整批自动跳过**，不可保留；文案 `import_reason_duplicate` 已用「疑似重复」，但 `import_status_duplicate` 仍是「重复跳过」 | 需：逐条「保留 / 跳过」+ 文案统一 |
| 账户编辑 | `TransactionEditViewModel` 只观察 `observeActiveAccounts()`；编辑引用了已归档账户的旧账单时 `applyDefaultAccountSelection` 会**把账户悄悄重置成第一个账户** | 需：编辑时保留原账户（含已归档）并显示「已归档」标签 |
| 未归属账单 | 无任何检测/归属 UI；`transactions.account_id IS NULL` 即 V1 历史账单 | 需：检测 + 批量归属 + 余额重算 |
| 总资产命名 | `chart_total_assets` =「总资产」 | 改「账户总余额」 |
| 周期选择器性能 | V2 Risk C 已做周/月/年有界聚合（`observeWeekCounts` 等） | 已满足，仅回归验证 |
| 备份恢复 | `BackupSerializer` 已含 recurring 全字段 JSON 往返 | 需兼容新增 `anchor_day_of_month`（旧备份缺字段时回退推导） |
| 测试 | JVM 单测 11 个文件（含 RecurringTransactionCalculatorTest、CsvImportParserTest 等）；仪器测试 MigrationTest、AccountBalanceConsistencyTest | 各 Phase 补对应用例 |

## 2. 阶段划分与任务

### Phase 0：基线确认
- [x] `gradlew assembleDebug` + `testDebugUnitTest` 全绿，确认 V2 无回归起点。

### Phase 1（P0）：搜索分类 / 账户选择器
> 基线第 5 章。目标：图标 + 短文字快速识别。

- [x] `ui/search/CategoryPickerDialog.java`：MaterialAlertDialog + RecyclerView 网格（`GridLayoutManager`，3/4 列按屏幕宽度自适应）
  - 每项 = Emoji 图标 + 分类名；选中态用 `primary` 边框 + `primary_light` 背景 + 勾选标记（不单靠颜色）
  - 首项「全部分类」；分类为空时显示空态 +「去分类管理」入口
  - 长列表纵向滚动
- [x] `ui/search/AccountPickerDialog.java`：图标 + 账户名 + 账户类型 的列表弹窗（**不显示余额**）
  - 账户项图标沿用 `AccountTypes` 类型图标映射；首项「全部账户」
  - 含已归档账户（历史账单可能落在归档账户上，需可筛），归档项带「已归档」标注
- [x] 复用改造：新建 `ui/adapter/PickerCategoryGridAdapter`、`PickerAccountAdapter`（或扩展现有 Adapter，以实际最小改动为准）
- [x] `activity_search.xml`：`categoryInput` / `accountInput` 由 AutoCompleteTextView 改为只读输入框（点击弹选择器），文本回显当前选择
- [x] `SearchActivity`：移除 `setSimpleItems` 逻辑，接入弹窗回调 `setCategoryId` / `setAccountId`；旋转重建后按 filter 回填
- [x] **P1 最近使用**：`ui/search/RecentFilterStore.java`（SharedPreferences，最多 3 条）在两个选择器顶部展示「最近使用」快捷区；无记录不显示
- [x] 资源：`dialog_category_picker.xml`、`dialog_account_picker.xml`、item 布局、`bg_picker_item_selected.xml`、strings

### Phase 2（P0）：图表趋势横轴优化
> 基线第 7–10 章。目标：数据点完整、标签自适应、末标签不裁切、气泡不越界。

- [x] `LineChartView` 增加绘图区安全边距：`chartPaddingLeft/Right`（取值约 12dp，来自 dimens），首末数据点不再贴容器边缘
- [x] 标签与数据点解耦强化：抽静态纯函数 `ChartAxisLabels.select(count, labelWidthsPx, availablePx)` 供 JVM 测试
  - 周（7 点）/ 年（12 点）在宽度足够时全显；不足时按基线降采样（年：1/3/5/7/9/11 月）
  - 月视图：1/5/10/15/20/25 + **末日强制显示**；宽度不足再降采样为 1/7/14/21/28 + 末日
  - 降采样判据 = 相邻标签像素间距 ≥ 预设最小间距（不缩小字体，优先减标签）
  - 首标签左对齐防左裁切、末标签右对齐防右裁切（`Paint.Align` 按位置切换）
- [x] 最高点气泡避让维持并补测试：顶部安全距离内下移、左右越界内移（现有逻辑抽为可测几何函数 `clampBubble(...)` 或保持内联 + 视觉验证）
- [x] 横向滚动：月/年默认不做（基线 10.1）；长周期局部横滑仅预留说明，不实现
- [x] 单测 `ChartAxisLabelsTest`：28/29/30/31 天、7 天、12 月、极窄宽度、末日强制

### Phase 3（P0）：周期账单日期稳定性
> 基线第 14–15、25 章。目标：从原始锚点重推，消除月末漂移。

- [x] `RecurringTransactionEntity` 新增 `@ColumnInfo(name = "anchor_day_of_month") public int anchorDayOfMonth`（仅 MONTHLY/YEARLY 使用；equals/hashCode 同步更新）
- [x] `AppDatabase`：version 3→4，新增 `MIGRATION_3_4`
  - `ALTER TABLE recurring_transaction ADD COLUMN anchor_day_of_month INTEGER NOT NULL DEFAULT 0`
  - 回填：`anchor_day_of_month = CAST(strftime('%d', start_date/1000, 'unixepoch', 'localtime') AS INTEGER)`
  - 验证：账单/账户/预算/周期账单 0 丢失、外键仍 RESTRICT
- [x] `GenerateRecurringTransactionsUseCase` 重写推进逻辑（锚点重推，不继承夹取结果）：
  - 月：`目标月 = 当前发生日所在月 + interval`，`日 = min(anchorDay, 当月最大天数)`
  - 年：`目标年 = 当前发生日所在年 + interval`，月固定锚点月，`日 = min(anchorDay, 当月最大天数)`（2/29 闰年规则自然覆盖）
  - 日/周逻辑不变；`collectDueDates` 增加 anchor 参数；保留 `MAX_OCCURRENCES_PER_RULE`、endDate、幂等语义
- [x] 写入链路：`saveRecurring` 统一 `anchorDayOfMonth = day(startDate)`（新建与改期都重算）；`BackupSerializer` 写出新字段、读取旧备份缺字段时按 `day(start_date)` 回退；`RestoreUseCase` 兼容
- [x] 更新调用方：`RecurringViewModel`、`BookkeepingRepository.confirmDueRecurringSync`
- [x] `RecurringTransactionCalculatorTest` 补用例：1月31→2月28→3月31、1月30→2月28→3月30、2月29→非闰年2月28→闰年2月29、interval>1、end_date 截断、多期补生成、停用不生成

### Phase 4（P0）：历史账单账户归属
> 基线第 11–12 章。目标：消除「记过钱但账户里没有」的认知断层；不自动猜测。

- [x] `TransactionDao`：`countUnassigned()`（`account_id IS NULL`）、`assignUnassigned(accountId, updatedAt)` 返回影响行数
- [x] `BookkeepingRepository`：`observeUnassignedCount()`、`assignUnassignedTransactions(accountId, callback)`（单事务：批量 UPDATE → 重算全部账户余额）
- [x] `AccountManageActivity`：进入时检测 `count > 0` 且用户未永久关闭过提示 → 弹「发现未归属账单」对话框（N 笔、说明不影响余额、[暂不处理][去设置]）
  - 「去设置」→ 批量归属对话框：列出未归档账户（图标+名称+类型）单选 → [取消][确认归属] → 确认后归属 + Snackbar 显示归属笔数
  - 「暂不处理」用 SharedPreferences 记忆，不再每次打扰
- [x] 回归验证：归属后对应账户余额增加、总支出统计不变、转账不受影响（仪器测试 `AccountBalanceConsistencyTest` 扩展或新增）

### Phase 5（P1）：搜索 / 导入 / 账户细节
> 基线第 16–18、26 章。

- [x] **疑似重复可保留**：`ImportPreviewAdapter` 重复行加「保留 / 跳过」切换；`ImportPreview`/`ImportViewModel`/`ImportTransactionsUseCase.commit` 支持「保留集」写入；结果统计把保留行计为成功
- [x] 文案统一：`import_status_duplicate` →「疑似重复跳过」；`import_desc`、`import_preview_hint` 措辞对齐「疑似重复」
- [x] **编辑旧账单保留已归档账户**：`TransactionEditViewModel` 编辑态补拉取账单原账户（已归档也返回）合并进候选；`TransactionEditActivity` 对已归档账户显示「（已归档）」后缀；保存不再被重置
- [x] **总资产改名**：`chart_total_assets` →「账户总余额」；账户相关 UI 若有同义文案一并统一
- [x] 搜索统计口径回归（共 N 笔含转账、收支不含转账）——已有实现，验证即可

### Phase 6：测试、性能与回归
