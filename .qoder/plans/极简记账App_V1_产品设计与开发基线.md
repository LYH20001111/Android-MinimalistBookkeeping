# 极简记账 · V1.0 产品需求与设计基线

> 快速记账 · 清晰分析 · 月度预算

| 产品定位 | 核心闭环 | 技术路线 | 数据策略 |
|:---|:---|:---|:---|
| 面向大众，重点服务上班族 | 记录 → 统计 → 分析 → 预算 | Android + Java + Room | V1 本地优先，无需登录 |

让用户用极少的操作记下一笔消费，并在周、月、年三个尺度上快速看懂自己的钱花在哪里。

## 2. 产品定位与设计原则

### 产品定位

一款"记得快、看得懂"的极简个人记账 App。首页负责记录事实，图表负责理解事实，我的页面负责管理产品。

### 2.1 核心用户问题

- "我刚刚花了多少钱？"——需要极低成本完成一笔支出或收入记录。
- "这个月为什么花这么多？"——需要清晰的周、月、年趋势与分类分析。
- "我这个月还能花多少？"——需要一个简单、可持续使用的月预算。

### 2.2 五条设计原则

1. **快**：从点击"+"到保存目标控制在 3～5 秒。
2. **简单**：默认只要求金额、类型、分类；日期/备注等尽量可选或默认。
3. **清晰**：优先展示总额、趋势、分类和周期对比，不用复杂财务术语。
4. **克制**：V1 不加入登录、云同步、OCR、AI、投资等会显著扩大范围的功能。
5. **本地优先**：无网络也可以完整记账、编辑、删除和查看统计。

| 暂不开发 | 原因 |

| 登录/注册/验证码 | 增加账号体系、网络依赖和隐私处理复杂度 |

| 家庭共享账本 | 涉及权限、多用户和同步 |
| 投资/贷款/资产管理 | 偏离 V1 极简记账核心 |

## 5. 页面一：记录

**页面职责**：记录事实。用户打开 App 后，应第一眼看到"今天花了多少"，并能在不经过复杂表单的情况下记下一笔。

### 5.1 页面结构

```
┌─────────────────────────────┐
│ 9月2日  ▼                   │
│                             │
│ 今日支出                     │
│ ¥126.50                     │
│                             │
│ 今日收入                     │
│ ¥0.00                       │
├─────────────────────────────┤
│ 今天                         │
│ 🍚 餐饮          -¥35.00    │
│ 🚇 交通          -¥6.00     │
│ ☕ 咖啡          -¥18.00    │
│                             │
│ 昨天                         │
│ 🛒 购物          -¥98.00    │
│           +                 │
├─────────────────────────────┤
│ 记录    图表    我的         │
└─────────────────────────────┘
```

### 5.2 新增记录

| 字段 | 必填 | 默认值 / 规则 |
|:---|:---|:---|
| 类型 | 是 | 默认"支出"，可切换"收入" |
| 金额 | 是 | 正数；内部以"分"为单位存储 |
| 分类 | 是 | 根据类型展示对应分类；默认选中常用分类 |
| 日期 | 是 | 默认当前业务日期，可调整 |
| 备注 | 否 | 最多 100 字 |
| 时间 | 否 | 默认当前时间 |

### 5.3 交互规则

- 输入 35 → 展示 ¥35.00；输入 35.8 → 展示 ¥35.80。
- 保存成功后返回记录页，并立即刷新今日统计和账单列表。
- 点击账单进入详情/编辑；删除必须二次确认。
- 没有任何账单时展示空状态和"记一笔"入口，而不是空白页面。
- 金额不得使用 double；建议使用 long 保存"分"。

## 7. 页面二：图表

**页面职责**：理解事实。用户进入图表后，10 秒内应该回答四个问题：花了多少、什么时候花得多、钱花在哪里、比上一周期多还是少。

### 7.1 信息优先级

- **第一层：核心数字** — 本周期收入 / 支出 / 结余
- **第二层：趋势** — 日趋势（周、月）/ 月趋势（年）
- **第三层：分类** — 分类金额 + 占比 + 排名
- **第四层：对比** — 本周期 vs 上一相同周期

### 7.2 周 / 月 / 年

| 视图 | 核心展示 | 趋势粒度 | 对比 |
|:---|:---|:---|:---|
| 周 | 本周收入、支出、结余、分类 | 按天 | 本周 vs 上周 |
| 月 | 本月收入、支出、结余、预算、分类 | 按天 | 本月 vs 上月 |
| 年 | 全年收入、支出、结余、分类 | 按月 | 本年 vs 上年 |

### 7.3 月视图建议

```

│                             │

│                             │
│ 消费分类                     │
│ 餐饮     ¥1,280   29.9%    │
```

## 8. 预算功能

V1 只做"月预算"，不做复杂的分类预算。预算的目的，是让用户看到"还能花多少"，而不是建立完整财务规划系统。

### 8.1 核心计算

```
剩余预算 = 月预算 - 本月支出
预算使用率 = 本月支出 / 月预算
结余 = 本月收入 - 本月支出
```

### 8.2 预算状态

| 使用率 | 状态 | 视觉建议 |
|:---|:---|:---|
| < 80% | 正常 | 保持主色 / 中性状态 |
| 80%～100% | 接近预算 | 使用 Warning 语义强调 |
| > 100% | 已超预算 | 使用 Danger 语义，并显示超出金额 |

```
本月预算
¥5,000
██████████████░░░░ 73.6%
已消费 ¥3,680
剩余 ¥1,320
```

## 11. 核心业务规则

| 规则 | 定义 |
|:---|:---|
| 收入/支出 | type 区分；支出计入消费统计，收入计入收入统计 |
| 结余 | 收入 - 支出 |
| 预算 | 只以支出计算，不把收入算作预算消耗 |
| 周期对比 | 周对周、月对月、年对年 |
| 日期 | 保存用户的业务日期；不要简单依赖保存瞬间的服务器时间 |
| 金额 | 以"分"的整数存储；展示层再格式化为元 |
| 删除 | 删除交易后所有相关统计立即重新计算 |
| 统计一致性 | 列表、首页概览、图表、预算必须来自同一数据源 |
| 空状态 | 无数据时显示引导；不允许图表展示"空白块" |

## 12. 数据库 ER 结构

V1 建议使用 Room + SQLite。核心表先控制在 4 张：Transaction、Category、Budget、UserSettings。账户、转账、用户等放到后续版本，避免为了"以后可能需要"而增加 V1 复杂度。

```
Category (1) ─────────────< Transaction (N)

Budget：按 year + month 唯一
UserSettings：本地单例配置

Category
  PK id
  name
  icon
  type
  sort_order
  is_default

Transaction
  PK id
  type
  amount
  FK category_id
  date
  time
  note
  created_at
  updated_at

Budget
  PK id
  year
  month
  amount
  created_at
  updated_at

UserSettings
  PK id
  theme
  first_launch
  created_at
  updated_at
```

### 12.1 Entity 字段建议

| Entity | 字段 | 类型 | 说明 |
|:---|:---|:---|:---|
| Transaction | id | Long | 主键 |
| Transaction | type | Int | 1=支出，2=收入 |
| Transaction | amount | Long | 金额，单位：分 |
| Transaction | category_id | Long | 外键 |
| Transaction | date | Long / String | 业务日期 |
| Transaction | time | String | 业务时间 |
| Transaction | note | String | 备注，可为空 |
| Transaction | created_at | Long | 创建时间 |
| Transaction | updated_at | Long | 更新时间 |
| Category | id | Long | 主键 |
| Category | name | String | 分类名称 |
| Category | icon | String | 图标标识 |
| Category | type | Int | 支出/收入 |
| Category | sort_order | Int | 排序 |
| Category | is_default | Boolean | 系统默认分类 |
| Budget | id | Long | 主键 |
| Budget | year | Int | 年份 |
| Budget | month | Int | 月份 |
| Budget | amount | Long | 预算，单位：分 |
| Budget | created_at | Long | 创建时间 |
| Budget | updated_at | Long | 更新时间 |
| UserSettings | id | Long | 单例主键 |
| UserSettings | theme | String | 主题设置 |
| UserSettings | first_launch | Boolean | 首次启动状态 |
| UserSettings | created_at | Long | 创建时间 |
| UserSettings | updated_at | Long | 更新时间 |

> **金额类型特别说明**：不要用 double/float 保存金额。统一使用 long，单位为"分"。例如 ¥35.80 → 3580L。

## 16. V1 验收标准

| 模块 | 验收标准 |
|:---|:---|
| 快速记账 | 从新增入口到保存目标约 3～5 秒；默认信息尽量少填 |
| 金额 | ¥35.80 能正确保存为 3580；统计不出现浮点误差 |
| 编辑/删除 | 编辑后列表与统计同步；删除有二次确认 |
| 周统计 | 能够查看本周收入/支出/结余、日趋势和分类 |
| 月统计 | 能够查看本月核心数字、日趋势、分类、预算和上月对比 |
| 年统计 | 能够查看全年收入/支出/结余、月趋势、分类、上年对比 |
| 预算 | 可设置月预算；可看到已用、剩余、使用率和超预算状态 |
| 分类 | 可新增/编辑/删除/排序；支出与收入分类分离 |
| 离线 | 断网情况下核心功能仍可用 |
| 空状态 | 首次使用和无数据场景均有明确引导 |

## 19. 产品最终定义

> **V1 最终产品定义**："极简记账"是一个以快速记录为入口、以周/月/年消费分析为核心价值、以月预算为控制手段的个人记账 App。

| 记录 | 图表 | 预算 | 我的 |
|:---|:---|:---|:---|
| 我今天花了什么？ | 我的钱花在哪里？ | 我这个月还能花多少？ | 我怎么管理这个 App？ |

**整个 V1 只围绕四个动作：**

> **记 → 看 → 懂 → 控**
>
> 当用户能够自然完成"记一笔 → 看统计 → 发现问题 → 用预算控制下一次消费"的闭环时，V1 即达到产品目标。
